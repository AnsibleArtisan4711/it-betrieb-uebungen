# 02.1 Laboraufbau und Installation von GLPI

| | |
|---|---|
| **Modul** | 02 Laboraufbau und Installation von GLPI (Priorität 1) |
| **Stufe** | Fortgeschritten |
| **Geschätzte Zeit** | 4 bis 6 Stunden (Schätzung; Lehrplan: 7 UE zu 45 Minuten = 5,25 Stunden) |
| **Werkzeuge** | Hyper-V, Ubuntu 24.04, Apache, MariaDB, PHP, GLPI |
| **Vorwissen** | Linux-Grundlagen (Shell, Paketverwaltung) |

> [!WARNING]
> **Stand der Prüfung: gegen Dokumentation geprüft, nicht ausgeführt.** Alle Befehle sind *nicht ausgeführt*. Paketnamen unter Ubuntu 24.04, das Verhalten des Web-Installers und das Verzeichnis, auf das der Webserver zeigen muss, sind *nicht bestätigt* und in der Installationsdokumentation der verwendeten GLPI-Version nachzulesen. Kennwörter sind Laborwerte.

## Lernziele

Nach dieser Übung kannst du

- die Architektur (Webserver, PHP, Datenbank) erklären
- GLPI mit seinen Abhängigkeiten installieren und das Web-Setup durchführen
- das Labor ohne Internet betreiben und einen Rückkehrpunkt anlegen

## Voraussetzungen

- drei VMs laut Tabelle sind installiert und starten
- Internetzugang für `asset-srv` nur während der Installation

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Webserver** | liefert die Weboberfläche aus (hier Apache) |
| **PHP** | Programmiersprache, in der GLPI geschrieben ist |
| **Datenbank** | speichert alle Daten (MariaDB oder MySQL) |
| **Checkpoint** | Hyper-V-Rückkehrpunkt, keine Datensicherung |
| **Web-Installer** | geführte Einrichtung im Browser |

## Testumgebung

| Was | Rolle in Modul 02 |
|---|---|
| `asset-srv` | Ubuntu 24.04 LTS Server mit GLPI, `192.168.110.10/24`, 2 vCPU, 4 GB RAM, 30 GB Platte, Benutzer `labadmin` |
| `win-client` | Windows 11 Evaluation, `192.168.110.20/24`, 4 GB RAM |
| `lx-client` | Linux-Client, `192.168.110.30/24`, 2 GB RAM |
| `Private-Switch` | privater Hyper-V-Switch ohne Verbindung zum Heimnetz (Modul 2: temporär ein Switch mit Internet) |
| Name | `asset.example.internal` über die hosts-Dateien |

## Aufgabe

### Aufgabe 1 – Anforderungen (Einheit 2.1)

Lies die Voraussetzungen der verwendeten GLPI-Version (Quelle siehe unten) und erstelle eine Tabelle: mindestens erforderliche PHP-Version, Datenbank samt Mindestversion, Pflicht-Erweiterungen von PHP, unterstützte Webserver. Vergleiche mit der PHP-Version, die Ubuntu 24.04 mitbringt (`php -v` nach der Installation; die Version ist *nicht bestätigt*).

### Aufgabe 2 – Netzwerk und Abhängigkeiten (Einheit 2.2)

1. Konfiguriere die drei VMs mit den Adressen aus der Tabelle (`netplan`, Datei unter `/etc/netplan/`, Name *nicht bestätigt*) und trage `192.168.110.10 asset.example.internal` in die hosts-Dateien ein (Linux: `/etc/hosts`; Windows: `C:\Windows\System32\drivers\etc\hosts`).
2. Gib `asset-srv` temporär Internet (zweite Netzwerkkarte mit Switch ins Internet) und installiere die Abhängigkeiten. Beispiel, Paketnamen *nicht bestätigt*:

```bash
sudo apt update
sudo apt install apache2 mariadb-server php libapache2-mod-php php-mysql php-curl php-gd php-intl php-xml php-mbstring php-bcmath php-zip
```

3. Prüfe, dass Apache läuft (`systemctl status apache2`) und die PHP-Version zur Mindestversion passt.

### Aufgabe 3 – GLPI installieren (Einheit 2.3)

1. Lege Datenbank und Benutzer an (Laborwerte, Kennwort in keiner realen Umgebung verwenden):

```sql
CREATE DATABASE glpi CHARACTER SET utf8mb4;
CREATE USER 'glpi_user'@'localhost' IDENTIFIED BY 'Lab-Passwort-2';
GRANT ALL PRIVILEGES ON glpi.* TO 'glpi_user'@'localhost';
FLUSH PRIVILEGES;
```

2. Lade das Release von der Projektseite (URL und Archivname *nicht bestätigt*), entpacke es in ein Verzeichnis unterhalb des Webverzeichnisses, setze Eigentümer (`www-data`) und Rechte und rufe die Seite im Browser auf `win-client` auf.
3. Durchlaufe den Web-Installer und notiere, wo das Verzeichnis für den Webserver (Dokumentenwurzel) laut Dokumentation der gewählten Version liegen muss.

### Aufgabe 4 – Absicherung und Rückbau (Einheit 2.4)

Ändere die Kennwörter der Beispielkonten (Bestand laut Installationsdokumentation, *nicht bestätigt*), entferne die zweite Netzwerkkarte, prüfe mit `ping` und `ip route`, dass der Server das Internet nicht erreicht, und lege den Checkpoint `nach-Modul-2` an.

## Hinweise

- Lies zuerst die Voraussetzungen der **verwendeten** Version: GLPI 10 und 11 haben unterschiedliche Mindestversionen von PHP und Datenbank.
- Notiere Abweichungen von der Anleitung in `befehle-nicht-bestaetigt.md`.
- Ein Checkpoint ersetzt keine Datensicherung (siehe Modul 8).

## Kontrollfragen

1. Welche Aufgaben haben Webserver, PHP und Datenbank bei GLPI?
2. Warum müssen Standardkennwörter nach der Installation geändert werden?
3. Warum ist ein Checkpoint keine Datensicherung?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Aufgabe 1 (Stand der Quelle vom 13.11.2026, GLPI 11.0.x).** PHP mindestens 8.2; Datenbank MariaDB mindestens 10.6 oder MySQL mindestens 8.0; Webserver Apache 2, Nginx, lighttpd oder IIS (mit URL Rewrite); Pflicht-Erweiterungen laut Quelle unter anderem dom, fileinfo, filter, libxml, simplexml, tokenizer, xmlreader, xmlwriter, curl, gd, intl, mysqli, session, zlib sowie bei GLPI 11 zusätzlich bcmath, mbstring, openssl. Für GLPI 10 gelten niedrigere Mindestversionen (PHP 7.4, MariaDB 10.2 oder MySQL 5.7). Die PHP-Version von Ubuntu 24.04 ist im Labor zu notieren.

**Aufgabe 3.** Zielzustand: Die Weboberfläche ist unter `http://asset.example.internal/` erreichbar, der Web-Installer ist abgeschlossen und meldet keine fehlenden Erweiterungen.

**Aufgabe 4.** Zielzustand: Beispielkonten haben neue Laborkennwörter, der Server erreicht das Internet nicht mehr, ein Checkpoint `nach-Modul-2` existiert.

**Fragen.** (1) Webserver liefert aus, PHP führt die Anwendung aus, die Datenbank hält die Daten. (2) Sie sind öffentlich bekannt. (3) Er friert den Zustand der VM ein, schützt aber nicht vor Defekt oder Fehlern des Speichers und enthält die Fehler mit.

</details>
