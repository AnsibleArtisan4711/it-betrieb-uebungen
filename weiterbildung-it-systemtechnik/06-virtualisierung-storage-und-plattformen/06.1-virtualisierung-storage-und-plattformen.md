## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Klon** | Kopie einer VM mit neuer ID; identische Inhalte (Hostname, IP, SSH-Schlüssel) müssen bereinigt werden. |
| **Dynamic Memory** | Der Host verteilt RAM dynamisch zwischen Startup-, Minimum- und Maximum-RAM. |
| **Überbuchung** | Summe der Maxima größer als der physische Speicher. |
| **Checkpoint** | Zustand einer VM zu einem Zeitpunkt (Learn: Standard oder Produktion). **Kein Backup.** |
| **`.avhdx`** | Differenzdatei eines Checkpoints; wächst mit den Änderungen. |
| **DAS / NAS / SAN** | Direkt angebundener / Netzwerk- / Blockspeicher im Speichernetz. |
| **Privat / intern / extern** | Switch-Typen: nur VMs / VMs und Host / mit physischer Netzkarte. |

## Hintergrund

### Klon und Identität

Eine VM-Kopie enthält alles, was die Quelle auch enthält: Hostname, IP-Adresse, SSH-Hostschlüssel, Maschinen-ID. Zwei Kopien im selben Netz stören sich (Adresskonflikt, Namenskonflikt, identische Hostschlüssel verwischen die Identität). Der isolierte Switch verhindert das; ein richtiges Template wird vor dem Klonen bereinigt.

### Dynamic Memory

*Startup RAM* steht beim Start zur Verfügung, *Minimum RAM* ist die Untergrenze, *Maximum RAM* die Obergrenze. Der Host verteilt zwischen VMs nach Bedarf. Das senkt den Bedarf im Mittel, erhöht aber die **Überbuchung**: Wenn alle Maxima gleichzeitig gebraucht werden, reicht der Speicher nicht.

### Checkpoints sind kein Backup

Ein Checkpoint liegt auf demselben Speicher wie die VM; fällt er aus, sind beide weg. Eine lange Kette von Checkpoints macht die VM langsamer und frisst Platz; bei datenbank- oder verzeichnisdienstähnlichen Systemen kann das Zurücksetzen zu Inkonsistenzen führen (Learn).

### Privat, intern, extern

*Privat*: nur VMs untereinander. *Intern*: VMs und Host (der Host erhält einen virtuellen Adapter). *Extern*: Anbindung an eine physische Netzkarte; dadurch Zugang zum Heim- oder Firmennetz. Das Labor verwendet **nie** externe Switches.

### Antworten auf die Kontrollfragen

1. Der **Standard**-Checkpoint speichert auch den **Speicherzustand** der laufenden VM; der **Produktions**-Checkpoint nutzt die Sicherungstechnik des Gasts (konsistenter Stand, keine Speicherinhalte; Learn). Beide liegen auf demselben Speicher wie die VM und ersetzen kein Backup.
2. Startup RAM: Speicher beim Start; Minimum RAM: Untergrenze, auf die der Host reduzieren darf; Maximum RAM: Obergrenze.
3. `-GenerateNewId`, weil die Kopie sonst dieselbe VM-ID wie das Original hätte (Konflikt auf dem Host); der isolierte Switch verhindert Konflikte der doppelten Adresse und Hostschlüssel im Labornetz.
4. DAS hängt direkt am Server (Ausfall des Servers = Speicher nicht erreichbar); NAS stellt Dateien über das Netz bereit (Protokolle wie SMB, NFS); SAN stellt Blockspeicher über ein Speichernetz bereit (zum Beispiel iSCSI, Fibre Channel); jeweils mit anderen Ausfallfolgen (Netz, Controller, Switches).
5. Jede Änderung nach dem Checkpoint wird in einer `.avhdx`-Datei gesammelt; je länger der Checkpoint besteht, desto größer die Datei. Beseitigung mit `Remove-VMCheckpoint` (Zusammenführen); dazu muss genug freier Platz da sein; `.avhdx` niemals direkt löschen.
